Features

Alles, was ein DNS-Log braucht.
Nichts, was du nicht brauchst.

📡

Live-Log in Echtzeit

Uhrzeit · Gerät · IP · Domain. Scrollen per Pfeiltasten, Bild-Tasten oder Mausrad — beim Hochscrollen pinnt die Ansicht, das Log läuft im Hintergrund weiter. Dazu Sparkline, Live-Rate und Zähler in der Statusleiste.

📱

Gerätefilter

Checkbox-Liste aller Geräte der Box — auch offline. Filter per MAC, gilt für IPv4 und IPv6.

🚫

Sperrliste

Treffer rot markiert oder „nur Treffer“. Subdomains matchen automatisch, hosts-Format wird verstanden.

✈️

Telegram-Alarm

Push bei jedem Treffer — mit Cooldown gegen Flut, asynchron, ohne die Anzeige zu bremsen.

🔁

Selbstheilend

Bricht die Aufzeichnung ab, meldet sich lauschbox mit Backoff neu an. Beim Beenden wird alles sauber gestoppt.

📊

Statistik der Sitzung

Top-Domains, aktivste Geräte und Treffer als Balkendiagramm — direkt im Menü.

Datei-Log

Web-UI

Taste w startet eine Weboberfläche (Port 8080): Schalter, Geräteauswahl und Live-Log im Browser, auch mobil. Ohne Login — nur im vertrauenswürdigen Heimnetz nutzen.

Setup

In drei Minuten am Start.

  1. 1

    FRITZ!Box vorbereiten

    • Benutzer mit Passwort anlegen (nicht „nur Kennwort“): System → FRITZ!Box-Benutzer → Benutzer hinzufügen, Recht „FRITZ!Box Einstellungen“.
    • TR-064 freischalten (für die Geräteliste): Heimnetz → Netzwerk → Netzwerkeinstellungen → „Zugriff für Anwendungen zulassen“.
  2. 2

    Werkzeuge installieren

    brew install wireshark python curl figlet
    sudo apt-get install tshark python3 curl figlet

    figlet ist optional (großes Banner). Fehlende Pflicht-Tools meldet lauschbox beim Start samt Installationsbefehl. Root-Rechte sind nicht nötig.

  3. 3

    lauschbox installieren

    curl -fsSL … | sh

    oder klassisch:

    git clone https://github.com/forbidden-fruits/lauschbox
cd lauschbox
./lauschbox
  4. 4

    Einrichten & loslegen

    1. [1] Verbindung Fritzbox — IP, Benutzer, Passwort (wird direkt per Login getestet)
    2. [2] Verbindung Telegram — optional, sendet eine Testnachricht
    3. [3] Gerätefilter — Geräte auswählen
    4. [4] DNS Logging — los geht’s

    Weitere Punkte: [5] Sperrliste anzeigen · [6] Statistik · [7] Logdatei Pfad (Ziel des Datei-Logs) · [8] Web-UI Port · [9] Ende. Der aktuelle Log-Pfad steht im Kopf des Hauptmenüs.

    Direkt ins Log starten: lauschbox --log

Web-UI

Bedienen im Browser.
Auch vom Sofa aus.

Taste w im DNS-Logging startet eine Weboberfläche. Sie spiegelt die Schalter des Terminals, lässt dich Geräte auswählen und zeigt das Live-Log — am Rechner genauso wie am Handy.

Was sie kann

  • Schalter: Gerätefilter, Sperrliste, Telegram, Pause, Datei-Log und „Puffer leeren“
  • Geräteauswahl: Checkbox-Liste, Speichern schreibt den Filter, Alle hebt ihn auf
  • Live-Log: neueste Einträge oben, Treffer rot, bis zu 500 Zeilen
  • Synchron: Änderungen im Browser erscheinen sofort im Terminal und umgekehrt (Browser aktualisiert alle 2 s)

Einschalten

  1. DNS-Logging starten (4 im Menü oder lauschbox -l)
  2. w drücken — die Statusleiste zeigt w ● und die Adresse
  3. Im Browser http://<Rechnername>:8080 öffnen

Port ändern: Menü [8] oder WEB_PORT in der lauschbox.env. Die Web-UI läuft nur, solange das Logging aktiv ist.

⚠️ Keine Anmeldung, lauscht auf allen Interfaces — nur im vertrauenswürdigen Heimnetz einschalten.

Konfiguration

Ein paar Textdateien. Fertig.

lauschbox sucht jede Datei zuerst im aktuellen Verzeichnis, danach unter ~/.config/lauschbox/. Neue Dateien landen dort, wo sie gefunden wurden — sonst in ~/.config/lauschbox/. Die .env-Dateien werden nur gelesen, nie als Shell-Code ausgeführt.

Dateien

DateiInhalt
.fritzbox.envFB_IP, FB_USER, FB_PASS
.telegram.envTG_TOKEN, TG_CHAT_ID
.devices.envDEVICE_FILTER (MACs oder ALL), DEVICE_FILTER_NAMES
blocklist.txtSperrliste
lauschbox.envEinstellungen (rechts) · LOG_FILE auch über Menü [7]
dns.logDatei-Log (Taste l)

⚠️ Die .env-Dateien enthalten Klartext-Zugangsdaten (Rechte 600) — nicht committen.

blocklist.txt

# Kommentar
example.com
tracking.example.org
*.ads.example.net
0.0.0.0 telemetry.example.com

Eine Domain pro Zeile · example.com trifft auch www.example.com · hosts-Format & *. werden verstanden · Änderungen greifen beim Einschalten mit s.

lauschbox.env — alles optional

# Scrollback-Puffer im Log
LOG_MAX_LINES=1000
# Zeilen in der Sperrlisten-Ansicht
BLOCKLIST_MAX_LINES=1000
# Aufzeichnungs-Interface der Box
CAPTURE_IFACE=1-lan
# Doppelte Anfragen ausblenden (Sek.)
DEDUPE_SECS=2
# Telegram: gleicher Treffer frühestens nach n Sek.
NOTIFY_COOLDOWN=30
# Gerätenamen auffrischen alle n Sek.
DEVICE_REFRESH_SECS=300
# Port der Web-UI (Taste w), 1024-65535 — auch über Menü [8] setzbar
WEB_PORT=8080
# Datei-Log (absoluter Pfad) — auch über Menü [7] "Logdatei Pfad" setzbar
LOG_FILE=/Users/du/.config/lauschbox/dns.log

FAQ & Grenzen

Gut zu wissen.

Was sieht lauschbox — und was nicht?

Nur DNS-Anfragen, die bei der FRITZ!Box ankommen. Unsichtbar bleiben DNS-Cache-Treffer auf dem Gerät, verschlüsseltes DNS (DoH/DoT im Browser), iCloud Private Relay und VPN-Clients. Geloggt wird die angefragte Domain — nicht der Seiteninhalt.

Login fehlgeschlagen — was nun?

Einen Benutzer mit Passwort verwenden (nicht „nur Kennwort“), Recht „FRITZ!Box Einstellungen“ vergeben und nach Fehlversuchen die BlockTime der Box abwarten.

Die Geräteliste ist leer oder lädt nicht.

Prüfe, ob TR-064 freigeschaltet ist („Zugriff für Anwendungen zulassen“) und ob die IP stimmt.

Eine Domain fehlt im Log.

Ist der Gerätefilter aktiv (g drücken)? Kam die Antwort aus dem DNS-Cache? Nutzt das Gerät DoH, Private Relay oder VPN?

Keine Telegram-Nachricht.

Bot per /start kontaktiert? Chat-ID korrekt? Sperrliste (s) und Telegram (t) an? Derselbe Treffer wird höchstens alle 30 s gemeldet (NOTIFY_COOLDOWN).

Läuft auf der Box dauerhaft eine Aufzeichnung?

Nur solange lauschbox läuft. Beim Beenden — auch per Ctrl+C — wird sie wieder gestoppt.

Das Terminal ist nach einem Absturz kaputt.

reset oder stty sane eingeben.
